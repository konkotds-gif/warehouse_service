# Изменения

## 1.2.0 — 2026-11-05

### Вход через Active Directory
- Сотрудники входят доменной учётной записью (`ivanov`, `CORP\ivanov`, `ivanov@corp.local`). Пользователь платформы создаётся при первом входе.
- Роль (и при желании магазин/склад) назначается по группам AD при каждом входе; вложенные группы учитываются; при нескольких группах — старшая роль.
- «Настройки → Вход через Active Directory»: контроллеры домена (с переключением на следующий), LDAPS/StartTLS, корневой сертификат CA, base DN, сервисная учётка (пароль хранится зашифрованным), проверка подключения и пользователя, поиск групп AD, сопоставление «группа → роль».
- Локальные пользователи входят своим паролем без обращения к AD — локальный администратор остаётся запасным входом.
- Ежечасная сверка `ldap:sync`: отключённым в домене и убранным из групп закрывается доступ, их сеансы завершаются.
- Нужно PHP-расширение `ldap` (docs/INSTALL.md, раздел 9.2).

## 1.1.0 — 2026-11-05

### Приём и гараж клиента
- Размер шин выбирается из селектов: ширина (135–355), профиль (25–85), диаметр (R12–R24, R14C–R17C); индекс нагрузки/скорости — необязательное поле. Для нестандартных размеров (31x10.5 R15) есть переключатель «Другой формат».
- Бренд шин — селект с текстовым поиском по справочнику `tire_brands` (187 брендов, начальный список заливается миграцией); бренда нет в списке — можно оставить свой вариант. Модель шин — отдельное текстовое поле.
- В базе по-прежнему хранятся `tire_size` и `brand_model` («Бренд Модель»), API для 1С и бирки не меняются.

## 1.0.0 — 2026-11-01

Первая рабочая версия платформы хранения колёс.

### Учёт хранения
- Приём комплекта в магазине (мастер): клиент, автомобиль (госномер, марка, модель), гараж клиента с подстановкой данных, тариф, несколько комплектов в одном договоре.
- Уникальный номер договора, бирки 58×40 мм с QR (номер договора, одинаковый на всех бирках хранения), количество бирок = количеству колёс; HTML-печать и ZPL для термопринтера; квитанция клиенту.
- Конечный автомат статусов комплекта, все переходы в транзакции с блокировкой строки и записью в неизменяемый журнал движений (триггеры БД запрещают UPDATE/DELETE).
- Адресное хранение `XX_YY_ZZ`: генерация рядов и ячеек, подсказка свободной ячейки, этикетки ячеек.
- Перемещения магазин ⇄ склад со сканированием на отгрузке и приёмке, расхождения создают задания.
- Заказ к выдаче, подготовка, выдача только из «Готов к выдаче» и без долга; продление, просрочка, утилизация.
- Инвентаризация по ряду/складу с отчётом о расхождениях.
- Поиск по телефону, госномеру, номеру договора и QR; отчёты.

### Интерфейс
- Inertia + Vue 3 + Tailwind 4 в стиле «Диски Мира»; мобильные экраны кладовщика и водителя (ручной сканер штрихкодов в режиме клавиатуры или ввод вручную).
- PWA: установка на телефон, офлайн-очередь сканирований.
- Роли: продавец, кладовщик, водитель, руководитель магазина, администратор.

### Интеграция с 1С:УТ 10.3
- REST API v1 (JSON/XML), ключи с белым списком IP, идемпотентность по `Idempotency-Key`.
- Transactional outbox с курсором и подтверждением, справочники, оплаты, долг.
- Контроль неподтверждённых событий, документация `/docs/api`.

### Эксплуатация
- `deploy.sh` (релизы + симлинк, откат), CI на GitHub Actions (MariaDB 10.11, Pint, тесты, сборка фронтенда).
- Импорт текущих хранений из CSV, команды `user:create`, `onec:key`.
