# Изменения

## 1.3.4 — 2026-11-05

### Раздел «Автомобили»
- Новый пункт меню «Автомобили» (для ролей с доступом к клиентам): все машины клиентов с поиском по госномеру, VIN, марке/модели, ФИО и телефону владельца. Фильтры «Колёса на хранении» и «Без номеров».
- Карточка автомобиля: владелец, данные авто, комплекты гаража с адресами хранения, все договоры хранения этой машины, история владельцев. Кнопка «Принять на хранение» открывает мастер приёма с выбранной машиной.
- У автомобиля появились VIN / номер кузова, год выпуска, цвет и примечание.
- Новый автомобиль можно завести прямо в разделе, выбрав владельца. Госномер в разделе уникален на всю базу: если такая машина уже есть у другого клиента, платформа предложит сменить владельца.
- «Сменить владельца» (авто продали): договоры остаются за прежним владельцем, комплекты гаража по выбору переходят вместе с машиной или отмечаются «продан / утилизирован». Пока колёса машины на хранении, смена владельца запрещена. Каждая смена пишется в историю.
- Удаление ошибочной карточки авто (право «исправления»), если её колёса не на хранении. Договоры сохраняют ссылку на машину.
- Из гаража клиента, списка и карточки договора теперь можно перейти в карточку автомобиля.

## 1.3.3 — 2026-11-05

### Инвентаризация: поштучный счёт колёс
- Сначала сканируют ячейку, затем бирку на каждом колесе. Каждый скан засчитывается как одно колесо: «02_01_01: 000123 — колесо 3 из 4».
- Колёса одного договора могут лежать в разных ячейках (например, 3 в одной и 1 в другой), и каждую часть сканируют в своей ячейке. Под полем скана видно, что уже найдено в текущей ячейке.
- Лишний скан, когда все колёса договора уже найдены, не засчитывается. Сообщение показывает, где они найдены. Кнопка «Отменить последний скан» убирает ошибочный скан.
- В отчёте появились «Колёс найдено N / M», «Недостача колёс» (найдено 3 из 4) и «Колёса в разных ячейках». «Не на своём месте» и «Лишние» показывают раскладку по ячейкам.
- «Завершить и исправить»: если комплект целиком лежит в другой ячейке, ему назначается адрес той ячейки, где больше колёс. По недостаче колёс создаётся задание «расхождение». По колёсам в разных ячейках создаётся задание собрать их в ячейку по адресу комплекта.

## 1.3.2 — 2026-11-05

### Подтверждения во всплывающем окне платформы
- Все системные окна браузера `confirm()` заменены на модальное окно в стиле платформы: отгрузка и отмена ведомости, «убрать из ведомости», отмена перемещения, удаление комплекта из перемещения, удаление ключа API и настроек входа через Active Directory. Окно закрывается клавишей Esc или кликом мимо окна, а при переходе на другую страницу закрывается само.
- Счётчик «колёс N / M» в ведомости учитывает комплекты, отсканированные до появления поштучного счёта (миграция дозаполняет `wheels_out`/`wheels_in`).

## 1.3.1 — 2026-11-05

### Поштучный скан колёс при погрузке и приёмке
- Бирки на колёсах одного комплекта одинаковые, поэтому каждый скан засчитывается как одно колесо: «000123: колесо 2 из 4». Комплект считается погруженным или принятым, когда набрано столько колёс, сколько указано в договоре.
- Лишний скан (то же колесо отсканировали ещё раз) не засчитывается: звучит сигнал ошибки и выводится «Лишний скан: … уже погружен полностью (4 из 4)».
- В ведомости видно «колёс 6 / 8», по каждому комплекту «3 / 4». Ошибочный скан можно отменить кнопкой «−1» или сбросить весь комплект.
- Если отгрузить комплект, погруженный не полностью, он уйдёт с фактическим количеством колёс, и по нему будет создано задание «расхождение». Так же при завершении приёмки фиксируется фактически принятое количество.
- Если колёс действительно другое число, его можно указать кнопкой и отсканировать бирку один раз, как раньше.
- Миграция: поля `transfer_lines.wheels_out`, `transfer_lines.wheels_in`.

## 1.3.0 — 2026-11-05

### Перемещения, пул перевозок и ведомость водителю
- Перемещение создаётся без сканирования: выбрали комплекты одного или нескольких договоров — оно сразу в статусе «Ожидает погрузки» и попадает в пул «Задания → Перевозки». Страницу можно закрыть и вернуться в любой момент: незавершённые перемещения показываются вверху списка.
- До отгрузки перемещение можно дополнить комплектами других договоров («+ Добавить комплекты») или убрать лишний комплект. При создании нового перемещения из той же точки система предлагает дополнить уже существующее. Отмена — только с подтверждением.
- Когда приезжает водитель, в «Перевозках» отмечают одно или несколько перемещений и формируют **ведомость на перевозку** (`Р00001`): водитель, автомобиль, маршрут.
- Бирки сканируются при погрузке на экране ведомости сразу по всем её перемещениям, со сверкой «погружено / не хватает»; отметку можно снять. Отгрузка — по факту скана: неотсканированные комплекты остаются на месте и возвращаются в пул отдельным перемещением, перемещения без единого скана — целиком возвращаются в пул.
- Печать: ведомость на перевозку (сводка + комплекты по каждому перемещению, подписи «отпустил / водитель / получатель») и накладная водителю по одному перемещению.
- Приёмку можно вести и по ведомости (водитель привёз несколько перемещений); ведомость закрывается, когда приняты все перемещения.
- Миграция: таблица `trips`, поле `transfers.trip_id`.

## 1.2.0 — 2026-11-05

### Вход через Active Directory
- Сотрудники входят доменной учётной записью (`ivanov`, `CORP\ivanov`, `ivanov@corp.local`). Пользователь платформы создаётся при первом входе.
- Роль (и при желании магазин/склад) назначается по группам AD при каждом входе; вложенные группы учитываются; при нескольких группах — старшая роль.
- «Настройки → Вход через Active Directory»: контроллеры домена (с переключением на следующий), LDAPS/StartTLS, корневой сертификат CA, base DN, сервисная учётка (пароль хранится зашифрованным), проверка подключения и пользователя, поиск групп AD, сопоставление «группа → роль».
- Локальные пользователи входят своим паролем без обращения к AD — локальный администратор остаётся запасным входом.
- Ежечасная сверка `ldap:sync`: отключённым в домене и убранным из групп закрывается доступ, их сеансы завершаются.
- Нужно PHP-расширение `ldap` (docs/INSTALL.md, раздел 9.2).

## 1.1.0 — 2026-11-05

### Приём и гараж клиента
- Размер шин выбирается из селектов: ширина (135–355), профиль (25–85), диаметр (R12–R24, R14C–R17C); индекс нагрузки/скорости — необязательное поле. Для нестандартных размеров (31x10.5 R15) есть переключатель «Другой формат».

- В базе по-прежнему хранятся `tire_size` и `brand_model` («Бренд Модель»), API для 1С и бирки не меняются.

## 1.0.0 — 2026-11-01

Первая рабочая версия платформы хранения колёс.

### Учёт хранения
- Приём комплекта в магазине (мастер): клиент, автомобиль (госномер, марка, модель), гараж клиента с подстановкой данных, тариф, несколько комплектов в одном договоре.
- Уникальный номер договора, бирки 58×40 мм с QR (номер договора, одинаковый на всех бирках хранения), количество бирок = количеству колёс; HTML-печать и ZPL для термопринтера; квитанция клиенту.
- Конечный автомат статусов комплекта, все переходы в транзакции с блокировкой строки и записью в неизменяемый журнал движений (триггеры БД запрещают UPDATE/DELETE).
- Адресное хранение `XX_YY_ZZ`: генерация рядов и ячеек, подсказка свободной ячейки, этикетки ячеек.
- Перемещения магазин ⇄ склад со сканированием на отгрузке и приёмке, расхождения создают задания.
- Заказ к выдаче, подготовка, выдача только из «Готов к выдаче» и без долга; продление, просрочка, утилизация.
- Инвентаризация по ряду/складу с отчётом о расхождениях.
- Поиск по телефону, госномеру, номеру договора и QR; отчёты.

### Интерфейс
- Inertia + Vue 3 + Tailwind 4 в стиле «Диски Мира»; мобильные экраны кладовщика и водителя (ручной сканер штрихкодов в режиме клавиатуры или ввод вручную).
- PWA: установка на телефон, офлайн-очередь сканирований.
- Роли: продавец, кладовщик, водитель, руководитель магазина, администратор.

### Интеграция с 1С:УТ 10.3
- REST API v1 (JSON/XML), ключи с белым списком IP, идемпотентность по `Idempotency-Key`.
- Transactional outbox с курсором и подтверждением, справочники, оплаты, долг.
- Контроль неподтверждённых событий, документация `/docs/api`.

### Эксплуатация
- `deploy.sh` (релизы + симлинк, откат), CI на GitHub Actions (MariaDB 10.11, Pint, тесты, сборка фронтенда).
- Импорт текущих хранений из CSV, команды `user:create`, `onec:key`.
