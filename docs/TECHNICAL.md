Раздел 8 плана считать заменённым этим документом.

### 2.2 База данных: MariaDB (уже стоит на сервере)

План v0.5 предлагал PostgreSQL, но на сервере уже работает **MariaDB**, которой управляет ispmanager (создание баз, пользователи, бэкапы из панели). Для объёма сети магазинов (десятки пользователей, десятки тысяч договоров) её достаточно, второй сервер БД ставить не нужно. **Решено Дмитрием 01.11.2026: используем MariaDB.**

Требование: **MariaDB 10.11 или новее** (нативный тип `UUID` появился в 10.7). Laravel поддерживает её отдельным драйвером `mariadb`.

**Как модель данных из плана (раздел 5) переносится на MariaDB:**

| В плане (PostgreSQL) | В MariaDB | Примечание |
|---|---|---|
| `serial`, `bigserial` | `BIGINT UNSIGNED AUTO_INCREMENT` | Laravel `$table->id()` |
| `uuid` | `UUID` | Laravel `$table->uuid()` |
| `jsonb` | `JSON` (= `LONGTEXT` + проверка `JSON_VALID`) | Для outbox/аудита этого достаточно, индексы по JSON не нужны |
| `timestamptz` | `TIMESTAMP` / `DATETIME`, всё хранится в UTC | Часовой пояс — в приложении |
| `text CHECK (x IN (...))` | `CHECK` (работает с 10.2) или `ENUM` | Статусы держим в PHP-enum + `CHECK` |
| `bool` | `TINYINT(1)` | Прозрачно в Laravel |
| Частичный уникальный индекс | Генерируемый столбец + `UNIQUE` | Например «один открытый договор на комплект гаража»: столбец `open_key = IF(status='open', garage_set_id, NULL)` |
| `pg_trgm` (нечёткий поиск) | Нормализованный госномер/телефон + индекс + `LIKE 'А123%'`; для «по середине» — `LIKE '%123%'` | На десятках тысяч записей это мгновенно |

**Инварианты из плана — где проверяются:**

- **Ячейка не переполнена** — в транзакции: `SELECT … FROM storage_cell WHERE id = ? FOR UPDATE`, подсчёт комплектов, затем размещение. InnoDB блокирует строку, два кладовщика не положат в одну ячейку одновременно.
- **У размещённого комплекта есть ячейка** — `CHECK (status <> 'placed' OR current_cell_id IS NOT NULL)`.
- **Журнал `movement` только дописывается** — триггер `BEFORE UPDATE` / `BEFORE DELETE` с `SIGNAL SQLSTATE '45000'`: любая попытка изменить или удалить запись отклоняется базой.
- Все таблицы — `InnoDB`, кодировка `utf8mb4`, сравнение `utf8mb4_unicode_ci`.

### 2.3 Версия PHP: добавить 8.4 для сайта платформы

На сервере сейчас **PHP 8.2**. Для нового проекта этого мало:

- **Laravel 13** (текущая версия) требует PHP **8.3+**. На 8.2 можно запустить только Laravel 12, а он уже получает лишь исправления безопасности — до февраля 2027.
- У самого **PHP 8.2 поддержка безопасности заканчивается 31.12.2026** — через два месяца.

**Решение:** в ispmanager 6 несколько версий PHP ставятся параллельно («Настройки → Версии PHP» → добавить 8.4 с модулем PHP-FPM), версия выбирается **для каждого сайта отдельно**. Существующие сайты остаются на 8.2, сайт платформы — на 8.4. Остальные сайты стоит перевести на 8.3/8.4 до конца года независимо от платформы.

Если добавить 8.4 по какой-то причине нельзя — запасной вариант: Laravel 12 на PHP 8.2 с обязательным обновлением PHP и Laravel до начала 2027. Не рекомендую.

    Transfer/             # перемещения

  Http/

  Console/                # команды для cron (просрочки, очистка)

### 3.2 Ключевые технические решения

- **Статусы комплекта — конечный автомат** (`App\Domain\Storage\SetStatus` — enum + таблица разрешённых переходов). Любой переход идёт через один сервис, который в одной транзакции: блокирует строку комплекта и ячейки, меняет статус/адрес, пишет `movement`, пишет событие в `integration_outbox`.
- **Адрес `XX_YY_ZZ`** хранится и как вычисляемое поле `storage_cell.address` (уникальный индекс), и валидируется регуляркой `^\d{2}_\d{2}_\d{2}$`. Виртуальные адреса (`М05`, `TR-…`, `ISSUED`) — это `current_location_id` без ячейки.
- **QR на бирках = номер договора** (одинаковый на всех бирках хранения). Сканер ищет сначала `wheel_set.qr_code`, затем `storage_contract.number` — так работают и старые бирки, и возможный суффикс `/2`.
- **Гараж клиента** — таблица `garage_set`. При приёме поля копируются из гаража в `wheel_set` (снимок «как приняли»), правка при приёме обновляет гараж.
- **Госномер** нормализуется при записи (верхний регистр, кириллица ↔ латиница по таблице похожих букв `A→А, B→В…`), поиск — по нормализованному значению (индекс + `LIKE`).
- **Журнал `movement` неизменяем**: в MariaDB триггеры `BEFORE UPDATE`/`BEFORE DELETE` с `SIGNAL SQLSTATE '45000'`.
- **Удаление — мягкое** (`SoftDeletes`) для клиентов, машин, договоров.

## 4. Сервер: настройка и ресурсы

### 4.1 Что должно быть установлено

| Компонент | Как ставим |
|---|---|
| nginx, PHP-FPM 8.4 | ispmanager: «Настройки → Версии PHP» → добавить 8.4; у сайта платформы выбрать 8.4 в режиме PHP-FPM (8.2 остаётся для других сайтов) |
| Расширения PHP | `pdo_mysql`, `mysqli`, `mbstring`, `intl`, `bcmath`, `gd` или `imagick`, `zip`, `xml`, `curl`, `redis`, `opcache` |
| MariaDB | Уже установлена; проверить версию ≥ 10.11 |
| Redis | `apt install redis-server`, слушает только `127.0.0.1` |
| Composer 2 | официальный установщик |
| Node.js 22 LTS | только если собираем фронтенд на сервере (иначе собираем в CI) |
| Supervisor | `apt install supervisor` — держит воркеры очередей (ispmanager этого не делает) |
| Git | для выкладки из репозитория |

### 4.2 Распределение 16 ГБ ОЗУ

Ориентир, если на сервере только платформа (при соседстве с другими сайтами — уменьшить пропорционально):

| Потребитель | Сколько | Настройка |
|---|---|---|
| ОС, ispmanager, nginx | ~1,5 ГБ | — |
| MariaDB | ~6 ГБ | `innodb_buffer_pool_size = 5G` (если MariaDB обслуживает и другие сайты — учесть их базы), `innodb_log_file_size = 1G`, `innodb_flush_log_at_trx_commit = 1`, `innodb_flush_method = O_DIRECT` (SSD), `max_connections = 150` |
| PHP-FPM | ~3 ГБ | `pm = dynamic`, `pm.max_children = 30` (≈ 80–100 МБ на процесс), `memory_limit = 256M` |
| OPcache | 256 МБ | `opcache.memory_consumption=256`, `opcache.validate_timestamps=0` в проде |
| Redis | 256–512 МБ | `maxmemory 512mb`, `maxmemory-policy allkeys-lru` для кэша |
| Воркеры очередей | ~0,5 ГБ | 2–4 процесса |
| Запас под кэш ФС | остальное | Linux использует свободную память под кэш диска — это нормально |

Для нагрузки сети магазинов (десятки одновременных пользователей, тысячи договоров в сезон) этого сервера хватает с большим запасом. Узкое место в пик переобувки — не железо, а скорость сети на складах.

### 4.3 Диск

- Фото комплектов: 2–4 фото × ~300 КБ после сжатия на сервере ≈ 1 МБ на договор. 10 000 договоров в год ≈ 10 ГБ/год. Фото старше N сезонов после выдачи — в архив **[решить]**.
- БД: даже при сотнях тысяч движений — единицы гигабайт.
- Логи: ротация `logrotate` / `daily` канал Laravel, хранить 30 дней.

## 5. Развёртывание

### 5.1 Окружения

| Окружение | Где | Назначение |
|---|---|---|
| `local` | ПК разработчика (Laravel Sail / Herd) | Разработка |
| `staging` | Тот же сервер, отдельный сайт `test-sklad.…` и отдельная БД | Проверка перед выкладкой, обучение сотрудников |
| `production` | Сайт `sklad.…` | Рабочая система |

### 5.2 Сайт в ispmanager

1. «Сайты → Создать»: домен платформы, владелец — отдельный пользователь (например `sklad`), обработчик — **PHP-FPM 8.4**.
2. Корневая папка сайта — **`…/current/public`** (не корень проекта: `.env` и код не должны отдаваться по HTTP).
3. SSL: Let's Encrypt через ispmanager, включить редирект на HTTPS.
4. Доп. конфигурация nginx (в ispmanager — «Конфигурационные файлы» сайта):

```nginx
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
location ~ /\.(?!well-known) { deny all; }
client_max_body_size 20m;   # фото с ТСД
```

5. Ограничение доступа (план, раздел 12): только внутренняя сеть/VPN — правило в «Брандмауэр» ispmanager или `allow/deny` в nginx. Для API 1С — белый список IP сервера 1С **[уточнить]**.

### 5.3 База данных

Создать базу и пользователя в ispmanager («Базы данных → Создать»: сервер MariaDB, кодировка `utf8mb4`), либо вручную:

```sql
CREATE DATABASE sklad CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'sklad_app'@'localhost' IDENTIFIED BY '***';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES, TRIGGER
  ON sklad.* TO 'sklad_app'@'localhost';
-- после миграций: запретить правку журнала движений
-- (MariaDB не умеет отзывать права на одну таблицу при грантах на всю базу —
--  поэтому неизменяемость журнала гарантируют триггеры из раздела 2.2)
```

Для создания триггеров при включённом binlog может понадобиться `log_bin_trust_function_creators = 1` **[уточнить]**.

### 5.4 Каталоги и выкладка

Схема «релизы + симлинк», чтобы выкладка и откат занимали секунды:

```
/var/www/sklad/data/app/
  releases/20261101-1030/   # код конкретной версии
  shared/.env               # секреты, общий для всех релизов
  shared/storage/           # фото, логи, кэш — общий
  current -> releases/20261101-1030
```

Скрипт выкладки (`deploy.sh` в репозитории, запускается под пользователем сайта):

```bash
set -e
REL=/var/www/sklad/data/app/releases/$(date +%Y%m%d-%H%M)
git clone --depth 1 --branch main git@github.com:konkotds-gif/warehouse_service.git "$REL"
cd "$REL"
ln -s ../../shared/.env .env
rm -rf storage && ln -s ../../shared/storage storage
composer install --no-dev --optimize-autoloader
npm ci && npm run build            # или скачать собранный public/build из CI
php artisan migrate --force
php artisan optimize               # config, route, view, event cache
ln -sfn "$REL" /var/www/sklad/data/app/current
php artisan queue:restart
# PHP-FPM перечитать (OPcache с validate_timestamps=0): перезапуск пула через ispmanager или
sudo systemctl reload php8.4-fpm   # имя сервиса зависит от сборки PHP в ispmanager [уточнить]
```

Откат: переключить `current` на предыдущий релиз и выполнить `php artisan queue:restart`. Миграции пишем обратимыми; разрушающие изменения схемы — в два релиза.

### 5.5 Фоновые процессы

**Планировщик Laravel** — одна строка в cron (ispmanager: «Планировщик (cron)», пользователь сайта):

```
* * * * * cd /var/www/sklad/data/app/current && php artisan schedule:run >> /dev/null 2>&1
```

Задачи по расписанию: пометка просроченных хранений (ночью), напоминания клиентам (этап 4), очистка `integration_inbox` старше 90 дней, проверка зависших событий outbox.

**Воркеры очередей** — Supervisor (`/etc/supervisor/conf.d/sklad-worker.conf`):

```ini
[program:sklad-worker]
command=php /var/www/sklad/data/app/current/artisan queue:work redis --queue=high,default --sleep=1 --tries=3 --max-time=3600
user=sklad
numprocs=2
autostart=true
autorestart=true
stopwaitsecs=60
stdout_logfile=/var/www/sklad/data/app/shared/storage/logs/worker.log
```

## 6. Интеграция с 1С:УТ 10.3

Схема и эндпоинты — в плане, раздел 9. Здесь — как это реализуется в Laravel.

| Элемент | Реализация |
|---|---|
| Направление | 1С — клиент, платформа — REST-сервер. 1С опрашивает очередь событий каждые 1–5 минут |
| Аутентификация | Middleware `ApiKey`: заголовок `X-Api-Key` + белый список IP; отдельный ключ для каждой учётки 1С, ключи хранятся в БД в виде хэша |
| Формат | По заголовку `Accept`: `application/json` или `application/xml`. Один `ApiResource` → два сериализатора. XML — для 1С в режиме совместимости 8.2 |
| Outbox | Таблица `integration_outbox`; запись события — в той же транзакции, что и изменение договора (`DB::transaction`) |
| Выдача событий | `GET /api/v1/integration/events?after={id}&limit=100` — курсор по `id`, без смещений |
| Подтверждение | `POST /api/v1/integration/ack` — пишет `delivered_at` и `onec_doc_guid` |
| Идемпотентность | Заголовок `Idempotency-Key` на все `POST/PUT` от 1С → таблица `integration_inbox` (уникальный ключ); повтор возвращает сохранённый ответ, тот же ключ с другим телом — `409` |
| Документация | Scramble: `/docs/api` (закрыт паролем) — 1С-программист видит все поля и примеры |
| Мониторинг | Событие не подтверждено 1С дольше 30 минут → уведомление администратору (Telegram/почта) |
| Блокировка выдачи при долге | Перед выдачей — проверка последнего значения долга из `PUT /contracts/{number}/debt`; если данным больше N часов — предупреждение продавцу |

Порядок работ и оценка для 1С-программиста — план, раздел 9.5.

## 7. Дизайн-система

Интерфейс платформы оформляется в стиле сайта онлайн-записи **zapis.diskimira.com** («Диски Мира»), чтобы сотрудники и клиенты (квитанции, SMS-ссылки) видели один бренд. Значения ниже сняты со скриншотов и являются ориентиром; точные цвета и шрифт — взять из CSS сайта (DevTools) **[уточнить]**.

### 7.1 Характер стиля

- **Тёмно-синий hero** с тонкой сеткой и мягким синим свечением справа и красным — слева внизу.
- **Красные кнопки-CTA** с лёгким градиентом и стрелкой `→`.
- **Синие акценты**: иконки в синих скруглённых плашках, выбранный элемент — заливка синим.
- **Белые карточки** со скруглением и тонкой рамкой на светло-сером фоне.
- **Надзаголовок секции**: красная черта + красный текст капсом («— ПОЧЕМУ ОНЛАЙН»), под ним крупный жирный заголовок.
- **Логотип** «Диски МИРА»: красное «Диски», синее «МИРА».

### 7.3 Типографика

- Шрифт: гротеск без засечек с кириллицей; заголовки очень жирные (800–900), как «Шиномонтаж без очереди». По виду — Inter или Manrope **[уточнить по CSS сайта]**. Шрифт подключаем локально (self-hosted), без внешних CDN — система работает во внутренней сети.
- Шкала: H1 48–64 px (только экран входа), H2 32–40 px, H3 20 px / 600, текст 15–16 px, подписи 13 px.
- Цифры в таблицах и адресах (`02_07_15`, номера договоров) — моноширинные цифры (`font-variant-numeric: tabular-nums`).

### 7.4 Формы и отступы

- Скругление: карточки **16 px**, кнопки и поля **10–12 px**, иконки-плашки **12 px**, чипы и бейджи — полностью скруглённые.
- Карточка: белый фон, рамка 1 px `--line`, тень почти незаметная; при наведении — чуть сильнее тень и синяя рамка.
- Сетка: контейнер ~1140 px, отступы между карточками 16–24 px, секции 64–96 px по вертикали.

## 8. Безопасность

- Доступ к веб-интерфейсу — только из внутренней сети/VPN; API 1С — по белому списку IP + ключ.
- HTTPS везде (Let's Encrypt через ispmanager; при закрытом от интернета домене — DNS-проверка или внутренний сертификат).
- ispmanager: вход в панель только с доверенных IP, двухфакторная аутентификация, SSH — только по ключам, `fail2ban`.
- MariaDB и Redis слушают только `127.0.0.1` (`bind-address = 127.0.0.1`).
- Пароли — `bcrypt/argon2` (Laravel по умолчанию), блокировка после 5 неудачных попыток, сессия — 12 часов (смена).
- ПДн по 152-ФЗ (ФИО, телефон, госномер): доступ по ролям, журнал действий, согласие в квитанции, выгрузки — только у ролей «Руководитель» и «Администратор».
- Обновления: `apt` и ispmanager — ежемесячно; `composer audit` и `npm audit` — в CI.

## 10. Мониторинг и эксплуатация

- **Healthcheck** `GET /up` (встроен в Laravel) + собственный `/health`: БД, Redis, очередь, возраст последнего подтверждённого события 1С.
- Внешний пинг раз в минуту (например UptimeRobot или скрипт на другом сервере) → Telegram.
- **Логи**: `storage/logs/laravel-YYYY-MM-DD.log`, уровень `warning` в проде; ошибки — в Telegram-канал администратора.
- **Ошибки интеграции**: события outbox без `ack` дольше 30 минут, `5xx` на API — уведомление.
- **Метрики для руководителя** (этап 4): заполненность складов, комплекты по статусам, просрочки.
